# TASK-041: этап 4 — вкладка «Настройки»

**Статус:** новая
**Ветка:** task/041-config-settings

## Зачем

Часть поведения бота (глобальный авто-ответ, часы работы, время дайджеста) теперь хранится
в `app_settings` и правится через Edge Function `admin` (`GET/POST /settings`), контракт —
`ADMIN_API.md` в основном репозитории (`ИИ агент для сайта`, ветка `task/041-mini-app-etap-4`).
Нужен экран в этом мини-аппе, чтобы `owner` мог менять настройки с телефона, а `manager` —
хотя бы видеть их.

## Контракт (уже готов и задеплоен к моменту публикации; сейчас пиши против него)

`GET /settings` (owner и manager) → массив:
```json
[{ "key": "auto_reply_enabled", "value": true, "value_type": "boolean",
   "title": "Авто-ответы бота", "description": "…", "scope": "auto_reply",
   "updated_by": null, "updated_at": "2026-09-12T09:00:00+00:00" }]
```

`POST /settings` (только owner; `manager` → `403 forbidden`) — тело `{ "key": "...", "value": ... }`,
ответ 200 — обновлённая строка того же вида. Ошибки: `400 unknown_setting` (нет такого ключа),
`400 bad_request` (значение не подходит по `value_type`).

Известные на сейчас ключи (могут появиться новые — экран должен рендерить ЛЮБОЙ набор
настроек из ответа `GET /settings`, а не хардкодить эти шесть):
`auto_reply_enabled` (boolean), `business_hours_start`/`business_hours_end`/`digest_time` (time,
формат `HH:MM`), `paused_reply_text_ru`/`_en` и `off_hours_text_ru`/`_en` (string).
`scope` сейчас — `auto_reply` или `schedule`, но тоже не хардкодь список: группируй по тому,
что реально пришло, в порядке первого появления.

## Что сделать

Это ОДНОСТРАНИЧНОЕ приложение без вкладок сейчас (`index.html`/`app.js`/`style.css`, без сборки,
единственный внешний скрипт — `telegram-web-app.js`, вендорить нельзя). Добавляешь вкладки:

1. Простой переключатель из двух вкладок вверху `<main>`, под заголовком/профилем:
   кнопки в стиле существующих `.chip` (см. `elements.chips`/`setupFilters` в `app.js`),
   RU/EN подписи через тот же объект `strings`/`t`. Первая вкладка — текущий дашборд
   (`#dashboard` + `#filters`), вторая — новая `#settings-panel` (скрыта по умолчанию,
   `hidden`). Дашборд остаётся вкладкой по умолчанию — ничего не меняется в существующем
   поведении, если пользователь на неё не переключился.
2. При первом открытии вкладки «Настройки» — `request("/settings")` (переиспользуй
   существующую функцию `request()`, она уже понимает коды ошибок и `X-Tg-Init-Data`).
   Дальше запросы не повторяй, пока не сохранили что-то (после успешного `POST` — обновить
   локальные данные из ответа, не перезапрашивать всё заново).
3. Рендер: секция на каждый `scope` (заголовок — сам `scope` человекочитаемо не переводи
   жёстко разметкой, просто выведи как есть или заведи маленький словарь `scope_auto_reply`/
   `scope_schedule` в `strings` с фоллбэком на сырое значение для незнакомого `scope`).
   Внутри — поле на каждую настройку: `title`/`description` из ответа сервера (уже готовый
   текст, не переводи повторно), виджет по `value_type`:
   - `boolean` → чекбокс/переключатель;
   - `time` → `<input type="time">`;
   - `string` → `<textarea rows="3">` (это тексты клиенту, могут быть длинными).
4. Роль `manager` (из уже загруженного `/me`, поле `role`): все поля `disabled`, кнопок
   сохранения нет. Это косметика для UX, не защита — сервер и так вернёт 403.
5. Роль `owner`: одна кнопка «Сохранить» на каждую группу (`scope`). По клику — по очереди
   `POST /settings` для каждого поля этой группы (даже не изменённого — полей мало, это
   проще и надёжнее, чем отслеживать dirty-состояние), дождаться всех, обновить экран
   значениями из последних ответов, показать короткое «Сохранено»/«Saved» и, если что-то
   упало, — текст ошибки как в остальном приложении (`t[error.key] || t.internal`).
6. Новые ключи в `strings.ru`/`strings.en`: подписи вкладок, `unknown_setting` (нет в словаре
   сейчас), подпись «Сохранить»/«Save», «Сохранено»/«Saved», read-only-пометка для manager
   («Доступно только для владельца» / «Owner only» или похоже — сформулируй сам, коротко).
7. Стили — переиспользуй существующие классы (`chip`, `dashboard-block`, `hint`, `footnote`
   и т.п. из `style.css`), добавляй новые правила только если без них реально не обойтись.
8. Подними `?v=` в `index.html` НЕ нужно — это делает Claude при публикации в `main`.

## Чего делать НЕЛЬЗЯ

- Не добавляй сборку/бандлер/npm-зависимости.
- Не хардкodь список из шести настроек — рендери по тому, что вернул `GET /settings`.
- Не пытайся публиковать в `main` — работай в ветке `task/041-config-settings`, мердж и
  публикацию (включая `?v=`) делает Claude после ревью.
- Не трогай существующий дашборд сверх добавления вкладок (переключение видимости, не
  переписывание).
